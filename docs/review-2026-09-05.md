# Client review — 2026-09-05

## Scope and verification

Reviewed the static client, saved-menu persistence/import/application, room
entry and delayed callbacks, bill discount allocation, and service-worker caching.
Read the checked-in Supabase schema/RPCs to identify integration limitations.
This is a scoped client review, not a claim that the entire service is bug-free
or a production security certification.

Validation: `node --test tests/regressions.test.cjs` — **22 tests pass**;
the entire inline JavaScript parses; `git diff --check` passes. Network failures,
realtime echoes, and delayed replies are simulated deterministically. No live
Supabase writes, fresh two-device tests, or browser-layout verification were
performed during this review. No SQL migrations are included or applied.

## Implemented changes

- Added side-by-side full-menu and saved-seasonal-set selectors to room creation,
  with English/Cantonese labels. Seasonal sets can be layered onto the selected
  full/default menu; matching names update prices without mutating the preset.
  Menu selectors cannot change during room creation.
- Removed the silent 200-record saved-menu truncation. Invalid/duplicate local
  IDs are repaired consistently, so entries remain addressable across reads.
- Validate saved settings/tallies before using them; reject inherited object
  properties masquerading as standard dish IDs in imported menus.
- Keep offline startup usable when the Supabase CDN script is unavailable.
  Shared-room operations still require the library/network; reload when online.
- Distribute discount cents by largest remainder rather than charging an empty
  last diner a negative discount to absorb rounding errors.
- Await seasonal room writes before exposing new local rows; serialize preset
  applications on the same device. Failures no longer close the import preview
  as though the entire operation succeeded.
- Deduplicate manual seasonal additions when the realtime echo beats the RPC
  response, and avoid clearing a newer draft after a slow acknowledgement.
- Remove both lookup directions when a menu item is archived.
- Ignore stale restore/resync/claim responses and old channel callbacks after a
  room/session change. A late join lookup cannot reopen a panel after offline
  mode was selected.
- Guard all join submit paths against reentry. Retain an acknowledged new diner
  ID when the subsequent snapshot refresh fails, so retry does not add another
  diner. Existing-diner joins also refresh their snapshot before entering.
  A pending join disables cancellation/picks until the request settles.
- Handle absent clipboard support for menu-link copying.
- Cache the canonical app shell for offline root and room-link navigation;
  bypass non-GET requests and leave unrelated origin caches alone. Cache v18.

## Remaining risks and improvement priorities

These were identified by reading the client/checked-in SQL; deployed database
parity has not been independently checked. They are **not fixed by this release**.

1. **Backend authorization (high priority if privacy is expected).** Anonymous
   SELECT policies currently use `true`, so room-code possession does not enforce
   read isolation. RPCs rely on bill IDs rather than authenticated membership.
   Design room-scoped capabilities/membership, rate limits, and corresponding RLS
   and RPC checks before treating bills as private.
2. **Transactional, retry-safe room setup.** Creation seeds menu items and diners
   through separate RPCs; individual seed errors are currently logged while the
   room may still open partially populated. A failed final refresh followed by
   retry can create a second room. Move room creation plus seeding into one
   idempotent transaction with a client request key. Similarly, an `add_diner`
   request committed by the server whose response is lost remains ambiguous;
   this review only prevents duplicates after an acknowledged add.
3. **Reconnect and optimistic-write reconciliation.** The first subscription
   skips resync, and a later snapshot can race realtime changes or pending taps.
   Failed optimistic taps currently show an error but are not automatically
   rolled back. Add a versioned snapshot/event boundary and explicit pending-write
   reconciliation, with two-client disconnect/reconnect tests before rollout.
4. **Server-enforced limits and cross-device menu merging.** The eight-diner cap
   is client-side in the checked-in SQL. Concurrent clients can exceed it or
   independently add the same seasonal name with different IDs. Enforce limits
   under a bill lock and define an atomic seasonal merge RPC. Menu identity and
   intentional same-name dishes need an explicit product decision.
5. **Maintainability and browser coverage.** Extract persistence, menu schema,
   calculations, and room transport from the single HTML file as a follow-up.
   Add automated browser tests for focus/blur auto-add, mobile dropdown widths,
   clipboard fallback, and service-worker upgrade behavior. Pin/vendor CDN
   dependencies for reproducible releases. Export local menus regularly; they
   are not account-synced backups.

## Manual acceptance checklist

Use a disposable bill and two independent browser profiles/devices, not an
existing meal's live bill.

- At narrow phone widths and on desktop, verify both menu selectors are usable
  side by side, in both languages, including long menu names.
- Choose a saved full menu, add a seasonal set, repeat the same set, and add a
  second set. Confirm no same-name duplicates, updated prices, and unchanged
  saved presets. Create the bill and compare both devices' menus and totals.
- Leave a diner name and a complete item name/price draft using Tab/touch; verify
  automatic addition. Verify Add still works and zero price is accepted.
- Join with Enter repeatedly and with existing-diner picks; verify only one diner
  is added. Inject a failed post-add refresh and retry without duplicate diners.
- Apply seasonal sets during slow/offline requests. Confirm only acknowledged
  rows appear and the failure is visible. Reload to compare with server state.
- Start a room lookup/resume, then choose offline. Confirm delayed responses do
  not move the app back into the room. Fork offline during a pending seasonal
  add/claim and ensure late callbacks do not mutate the offline copy.
- Test a tiny percentage discount with an empty last diner: no negative totals
  and discount cents sum to the displayed discount.
- Upgrade an installed PWA, then launch offline at the root URL and a room-link
  URL. The shell should load; joining a room still requires connectivity.
